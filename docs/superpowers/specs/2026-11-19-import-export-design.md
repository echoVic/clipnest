# 导入与导出设计

日期：2026-11-19
分支：`main`

## 目标

把历史、常用语和设置导出成一个文件，在另一台电脑（或重装后）导入，合并进现有数据，按内容去重。macOS 和 Windows 互相导入。

打码只影响显示，数据库里存的是原文，所以导出文件里会有密码和密钥。默认不导出敏感条目，要勾选才带上；导出前说明文件没有加密。

不在范围内：加密导出、定时备份、只导出一部分（按时间或类型挑）、导入别的剪贴板软件的数据。只支持 SQLite 存储，JSON 存储时提示先迁移。

## 文件格式

一个 ZIP，默认名 `Clipnest 导出 2026-11-19.zip`。JSON 用 Deflate 压缩，PNG 本身已压缩，用 Store。

- `manifest.json`：
  ```json
  {"format": "clipnest-export", "version": 1, "app": "0.1.17", "platform": "darwin",
   "exported": 1763520000000, "history": 1234, "images": 56, "phrases": 12, "secrets": false}
  ```
  `platform` 是 `runtime.GOOS`，`exported` 是 Unix 毫秒，`secrets` 表示是否带了敏感条目。数量只给人看，导入时不信它，按内容重新数。
- `history.json`：数组，从新到旧。每条只存内容、来源和时间，二选一：
  ```json
  {"text": "…", "source": "Safari", "created": 1763519000000}
  {"image": "images/<64 位十六进制>.png", "source": "预览", "created": 1763518000000}
  ```
  标题、摘要、类型、敏感标记、ID 都在导入时用 `newEntry` 和本机的隐私设置重新算，不从文件里取。图片文件名用条目 ID，只是引用，导入时按 PNG 内容重新算 ID。
- `images/<id>.png`：每张图片一个文件。
- `phrases.json`：`{"phrases": ["…", "…"]}`，按现在的顺序。
- `settings.json`：
  ```json
  {"retention": {"maxMiB": 512, "keepDays": 0, "maxEntries": 0},
   "imageText": true,
   "privacy": {"secrets": "mask", "clearSync": true, "ignore": []},
   "platform": "darwin",
   "shortcut": "<当前快捷键的 accelerator>",
   "excludedApps": [{"bundleID": "…", "name": "…"}]}
  ```
  快捷键和排除的应用跟平台有关，只在同一平台导入。快捷键写的是实际生效的那个，用默认快捷键时也写上。

不导出：暂停状态、外观、开机启动、Win+V 设置、数据位置、识图文字。识图文字导入后重新识别，和搬移数据目录时一样。

JSON 写出时关掉 HTML 转义，`<`、`>`、`&` 原样写。

## 导出

1. 「存储」页新的「导入与导出」组里点「导出…」。偏好设置显示「正在准备导出…」，后台统计条数。
2. 弹对话框（`Dialog.Message`，挂在偏好设置窗口上）：
   - 标题「导出历史、常用语和设置？」
   - 说明「历史共 X 条（其中 Y 张图片），常用语 Z 条，另有设置。导出的文件没有加密，拿到文件的人能看到其中的全部内容，包括常用语。」
   - 有敏感条目时加一句「有 N 条历史含密码或密钥，默认不导出。」，并给复选框「包含敏感条目（N 条）」，默认不勾。
   - 按钮「导出…」「取消」。
3. 选保存位置：默认在「下载」文件夹，默认文件名如上，过滤器 ZIP。
4. 后台写文件：
   - 先把还没写进数据库的历史写进去（和 `MoveTo` 一样拿 `h.writeMu`），然后放开锁。
   - 另开一个只用来读的数据库连接，在一个读事务里读完全部历史、常用语和设置。WAL 下这个事务看到的是开始那一刻的快照，所以导出期间复制照常记录，面板照常编辑，不设 `d.busy`。
   - JSON 设置文件（隐私、排除的应用、快捷键）在开始读之前从内存里取一份。
   - 写到目标旁边的 `<文件名>.part`，权限 0600，写完 `Sync`，改名成目标（已有同名文件就替换，保存对话框已经问过）。任何一步失败都删掉 `.part`。
5. 设置页提示「已导出到 …：X 条历史、Z 条常用语」，不含敏感条目时加「N 条敏感条目没有导出」。

敏感条目：文字历史里打了码的（`secret` 不为空），加上现在的规则能在里面认出密钥的。隐私设置是「照常记录」时历史里没有打码，也按规则认，免得密码随手导出去。图片不算。第 1 步统计和第 4 步导出用同一个判断。

导出期间「导入…」「导出…」灰掉。迁移、搬移、导入进行中（`d.busy`）时不能开始导出，提示「正在处理其他操作，请稍后再试」。

## 导入

### 第一遍：检查和计数

点「导入…」，选一个 ZIP（过滤器 ZIP）。后台读一遍，什么都不写，设置页显示「正在检查导入文件…」。

1. 打开 ZIP，按名字找 `manifest.json`、`history.json`、`phrases.json`、`settings.json`、`images/<id>.png`，别的文件不读。这几个名字重复出现算损坏。
2. `manifest.json`：`format` 不对就提示「这不是 Clipnest 的导出文件」；`version` 比 1 大就提示「这个文件来自更新版本的 Clipnest，请先更新」；小于 1 算损坏。
3. 防 ZIP 炸弹：不信 ZIP 头里的大小，每个文件都经过限长读取。
   - `manifest.json` 最多 64 KB，`settings.json` 最多 1 MB，`phrases.json` 最多 200 MB（500 条 × 64 KB，再算上转义）。超了算损坏。
   - `history.json` 边读边解析，不整个读进内存。单条在文件里超过 4 MB（512 KB 文字转义后的上限再加余量）算损坏。条数超过 `maxRetainedEntries`（100 万）算损坏。
   - 图片超过 8 MB 只算这一条无效。
4. 每条历史走 `newEntry`：文字非空、不超过 512 KB、UTF-8 有效；图片引用的名字必须是 `images/<64 位十六进制>.png` 且在 ZIP 里，不超过 8 MB，PNG 能读出尺寸且不超过 16000。不符合的这一条跳过，计入「无效」。
   - `created` 不大于 0 算无效；比现在晚的改成导入时刻。
   - `source` 不是有效 UTF-8 或超过 256 字节就清空，条目照常导入。
   - 文件里内容相同的多条只算一条，取较晚的时间和它的来源。
5. 按本机现在的隐私设置判断每条文字：命中忽略规则的，或者设置是「不记录」而认出了密钥的，不导入，计入「按本机隐私设置不导入」。和复制时 `applyPrivacy` 同一套判断。
6. 和现有历史比 ID：已有的计入「已有」，不再算新增。
7. 常用语：每条按 `checkPhraseText` 的规则（非空、UTF-8、不超过 64 KB）检查，无效的跳过；和现有常用语或文件里前面的文字完全相同的算「重复」；新增的接在最后，总数到 500 条为止，剩下的计入「放不下」。`phrases.json` 超过 500 条算损坏。
8. 设置：有 `settings.json` 时用现有的校验（`RetentionPolicy.validate`、`PrivacySettings.compile`、`ExcludedApp` 的校验、`parseShortcutBinding(runtime.GOOS, …)`）。任何一项不过，整份设置都不导入，对话框里写明。`platform` 和本机不同时，快捷键和排除的应用跳过、保留本机的。
9. 清理预估：把现有历史（只读 ID、时间、大小）和新增的合起来，按导入后的排列（见下面第二遍）模拟 `pruneSQL` 的三条规则，算出会清掉几条、其中几条是这次导入的。文件里的设置有效且保留策略和本机不同时，按文件里的策略再算一遍。

内存里只留每条的元数据（ID、时间、大小、是否新增），不留内容。100 万条大约几十 MB。

### 确认

弹对话框（`Dialog.Message`，挂在偏好设置窗口上）：

- 标题「导入「文件名」？」
- 说明逐行列出，是 0 的行不写：
  - 「导出于 2026-11-19 10:30，来自 macOS 上的 Clipnest 0.1.17」
  - 「历史：新增 A 条，已有 B 条」；已有的条目保留较晚的时间
  - 「按本机隐私设置不导入 C 条」
  - 「无效、已跳过 D 条」
  - 「常用语：新增 E 条，重复 F 条」；「常用语最多 500 条，G 条放不下」
  - 「按当前保留策略，导入后会清理 Z 条最旧的历史，其中 Y 条是这次导入的」
  - 勾选设置会改变清理条数时：「同时导入设置的话，按文件里的保留策略会清理 W 条」
  - 平台不同时：「快捷键和排除的应用来自 Windows，不会导入」
  - 设置无效时：「文件里的设置无效，不会导入：原因」
  - 「导入期间不记录新的复制。」
- 文件里有有效设置时，复选框「同时导入设置（覆盖当前设置）」，默认不勾。
- 按钮「导入」「取消」。

没有新增历史、没有新增常用语、也没有可导入的设置时，只显示数字和「没有可导入的新内容」，一个「好」按钮。

数字按第一遍时的数据算。确认之前可能又记了几条复制，写入时重新判断，结果以完成后的提示为准。

### 第二遍：写入

和一键迁移一样：

1. 主线程设 `d.busy`：剪贴板监听跳过、面板编辑和打开面板都被挡住。面板开着就先收起，交还它的读事务。设置页显示「正在导入…」，按钮都灰掉。
2. 后台 `Storage.Import`：拿 `s.mu` 和 `h.writeMu`，先把没写进数据库的历史写进去，再拿常用语的锁和数据库写锁。
3. 重新读一遍 ZIP，第一遍的检查全部再做一次（文件可能在两遍之间被换掉），在一个事务里：
   - 新增历史和复制走同一套写入（标题、摘要、搜索、`search_id`），图片的识图状态设为待识别。
   - 已有的条目：文件里的时间更晚，就改成文件里的时间和来源；否则不动。打码状态保持原样。
   - 所有历史按 `created` 从新到旧重新编号 `position`，时间相同时原有的在前、再按文件顺序。现在 `position` 本来就和最后一次记录的时间同序，这样导入的旧历史排进它该在的位置。
   - 常用语接在最后，规则同第一遍。
   - 勾了导入设置：写保留策略和识图开关。
   - 按最终的保留策略执行 `pruneSQL`。
   - 提交。失败就回滚，什么都没变。
4. 提交以后，勾了导入设置的话，再依次保存隐私设置、排除的应用、快捷键（同平台时）。它们是单独的 JSON 文件，不在数据库事务里。快捷键走设置页改快捷键的同一条路，注册失败就保留原来的快捷键。哪一项失败，提示里写明哪一项没改成，已导入的历史和常用语不回退。
5. 重新载入内存里的历史和常用语，清除 `d.busy`，刷新面板。识图队列开着就开始识别新图片。
6. 设置页提示「已导入：新增 A 条历史、E 条常用语」，后面跟跳过和清理的条数，以及设置的结果。

## 出错

| 时机 | 结果 |
|---|---|
| 取消对话框或文件选择 | 什么都不变 |
| 导出时读库或写文件失败（含磁盘满） | 删掉 `.part`，提示原因，数据不受影响 |
| 不是 Clipnest 的导出文件、版本更新、ZIP 或 JSON 损坏、超出大小或条数上限 | 第一遍就停，不弹确认，什么都不写，提示原因 |
| 单条历史或常用语无效 | 跳过并计数，其余照常导入 |
| 导入事务失败（含磁盘满） | 回滚，历史、常用语和设置都不变，提示「导入失败：…，数据没有改动」 |
| 事务提交后某项 JSON 设置没能保存 | 历史和常用语已导入，提示哪项设置没改成 |
| 导入或导出时正在迁移、搬移或导入 | 不开始，提示「正在处理其他操作，请稍后再试」 |
| JSON 存储 | 按钮灰掉，提示先迁移到 SQLite |

## 设置页

「存储」页在「历史保留策略」和「清理历史」之间加一组「导入与导出」：说明「把历史、常用语和设置导出成一个文件，或从文件导入并合并。」，按钮「导出…」「导入…」。JSON 存储时按钮灰掉，说明换成「请先迁移到 SQLite，再导入或导出。」。进行中的状态和结果显示在这一页底部的提示里，和设置页别的操作一样。

## 测试

单元测试（macOS 和 Windows CI 都跑）：

- 往返：导出后导入到空存储，历史（文字、链接、代码、图片）、时间、来源、顺序、常用语、设置都一样；ID、标题、摘要、类型重新算出来和原来一致；图片待识别。
- 合并：内容相同的保留较晚的时间和来源；导入的旧历史按时间排进中间；常用语去重、接在最后、到 500 条为止。
- 敏感条目：默认不导出，打码的和「照常记录」时规则认得出的都算；勾选后导出；导入时按本机隐私设置重新打码，「不记录」和忽略规则命中的不导入。
- 无效条目跳过并计数：空文字、超过 512 KB、编码无效、图片引用不存在或名字不合规、图片超过 8 MB 或读不出、`created` 不大于 0。时间在未来的改成导入时刻。
- 拒绝整份文件：不是 ZIP、`format` 不对、`version` 更新、JSON 损坏、名字重复、各文件超出上限、历史超过 100 万条、常用语超过 500 条。拒绝时存储一字未变。
- ZIP 炸弹：ZIP 头里写的大小比实际小的文件也在上限处停下，内存不会随文件变大。
- 失败不留改动：钩子让事务中途失败，历史、常用语、设置都和导入前一样；导出中途失败不留 `.part`。
- 清理预估：对话框里的 Z、Y、W 和实际清理的条数一致（两遍之间数据没变时）。
- 设置：不勾不改设置；勾了全部覆盖；别的平台的快捷键和排除的应用跳过；设置无效时整份不导入；快捷键注册失败时保留原来的。
- 导出不挡记录：钩子停住导出的读事务时，复制照常写进数据库，导出的文件里没有这条。
- 对话框文字：导出和导入确认里每一行的出现条件和数字。

真机测试（先问；空闲；保存恢复剪贴板；退出已安装的 Clipnest；用 `Clipnest.verify` 默认目录；测完清理）：

- Mac：造一些文字、图片、一条打码的密钥和几条常用语，导出两次（带和不带敏感条目），用 `unzip -l` 和 `manifest.json` 检查内容和权限；同一个文件导回本机，全部是「已有」。
- Win11 云桌面：把 Mac 导出的文件经剪贴板传进去，导入：看确认框的数字、「快捷键和排除的应用来自 macOS，不会导入」、勾选导入设置后保留策略和隐私设置生效；面板里图片显示、识图文字重新识别出来。

测不到：100 万条规模的真机导入导出（单元测试用生成的数据测上限和内存），Win10。
