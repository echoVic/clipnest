# v0.1.8 本地图片文字识别（OCR）

用户在 v0.1.7 发布后指示「开始开发本地 OCR 功能」。此前调研已确定使用 macOS Vision，通过 purego 调用，保持无 cgo；目标是让截图中的文字可以搜索和复制。本文件记录评测结论和实现范围，不另行审批。

## 评测与选型

在 macOS 26.6.2（Apple M2 Pro）上，用 purego 直接调用 `VNRecognizeTextRequest`，不使用 cgo。arm64 与 x86_64（Rosetta）构建都能识别，输出一致。系统首次加载模型需要数秒，之后小截图约 0.1 秒。

召回率指搜索词作为子串（不区分大小写）出现在识别文字中的比例；CER 为去空白后的字符错误率。语料与评分脚本位于 `testdata/image-text-eval/`，采用的配置可用 `TestImageTextEvaluation` 复现（见[验证记录](../../image-text-validation.md)）；其他配置由一次性探针测得，探针不随代码提交。

**小截图**：13 张，涵盖中文界面、中英混排、繁体、Go/TS/JSON 代码、终端报错、链接与数字，共 71 个搜索词。每种配置在独立进程中各运行 3 轮，输出完全一致。

| 配置（精确识别） | 召回率 | CER | 单图中位耗时 |
| --- | --- | --- | --- |
| 自动检测语言，关闭语言校正（采用） | 95.8% | 0.023 | 73 ms |
| 自动检测语言，语言校正 | 94.4% | 0.023 | 91 ms |
| 指定 zh-Hans、en-US，语言校正 | 81.7% | 0.052 | 92 ms |
| 指定 en-US，语言校正（中文变乱码） | 64.8% | 0.324 | 93 ms |
| 自动检测 + zh-Hans、en-US 两次识别 | 97.2% | 0.023 | 约 2 倍 |

指定中文模型时，代码中的 `(`、`:`、`{` 常被识别成全角符号；只用英文模型则无法识别中文。自动检测语言单次识别即可兼顾。两次识别只多找回 2 个搜索词，却要两倍的电量和时间。

**整屏截图**：7 张，1920×1080 至 6016×3384 及 1600×9000 长截图，含 1 倍与 Retina 密度的侧栏、代码、终端、中英文正文，共 121 个搜索词。下表在同一时段各运行两轮；机器负载较高，耗时取两轮范围。

| 方式 | 召回率 | 7 张合计耗时 |
| --- | --- | --- |
| 整图识别，语言校正 | 72.7% | 3.4–7.0 s |
| 整图识别，关闭语言校正 | 81.8% | 2.2–3.4 s |
| 分块：整图交给 Vision，按区域识别（regionOfInterest） | 98.3% | 7.8–10.3 s |
| 分块：Go 解码一次，每块编码为 PNG 识别（采用） | 96.7% | 6.0–7.9 s |

整图识别的主要问题是大图静默返回空结果：文字高度低于图片长边约 1/180 时，Vision 一行也不返回（例如 5K/6K Retina 屏上的 22 px 文字、2000 px 以上 1 倍屏上的 11 px 文字），调整 `minimumTextHeight` 或旧版识别模型都无效。因此长边超过 1900 px 的图片分成不超过 1900 px、重叠 250 px 的区域分别识别。每个区域负责中间部分，跨区域的行按逐字位置拼接，避免重复或截断；区域内保持 Vision 的阅读顺序。语言校正会把代码拆成 `tx. Commit()`、`config. yaml`，关闭后两组语料的召回率都提高，字符错误率不变，因此关闭。

两种分块的差别是逐字识别的偶发误差，并非系统性遗漏：regionOfInterest 漏掉 1920 px 截图中的两行；采用的方式把 `tx.Commit()` 识别成 `tx.Commıt()`、`config.yaml` 识别成 `config-yaml` 等，共漏 4 个搜索词。决定性的差别在大图：把整图交给 Vision 时，每个区域都要重新解码整张图片，2880×16000 长截图需 28 秒左右；Go 解码一次后只需 3–3.5 秒。

所有区域放在一次请求中，6016×3384 截图的内存峰值约 1 GB；每个区域单独请求、单独释放后约 250 MB、2 秒左右，2880×16000 约 320 MB。解码后的图片每像素 4 字节，16000×16000 截图峰值达 1.25 GB，因此只识别不超过 5000 万像素的图片（解码约 200 MB）。识别分块图片后立即把解码内存归还系统：否则闲置的应用在 46 MP 图片之后数分钟内仍占约 230 MB，归还后稳定在 60–95 MB。加载 Vision 框架本身几乎不占内存（约 6 MB），首次识别后系统保留模型等约 45 MB（小截图后为 51 MB）。随附脚本生成的 16 张无文字照片均未识别出文字。

`automaticallyDetectsLanguage` 要求 macOS 13，与 Clipnest 的最低系统版本一致。

## 行为

- 仅 macOS 且使用 SQLite 存储时可用。默认开启；「偏好设置 → 隐私 → 图片文字」可关闭。旧 JSON 存储提示迁移后可用，其他系统说明仅支持 macOS。
- 记录图片后，在后台逐张识别，不阻塞采集、粘贴或面板。识别在本机完成，不联网；不改变图片本身、条目标识、粘贴内容或保留策略的容量统计。
- 升级后自动补识别已有图片，从最新的开始。重新复制同一张图片沿用已有结果。
- 识别结果可搜索：并入该图片的搜索文本与片段索引，中文短词、代码标点和长查询沿用现有搜索语义。
- 有文字的图片，列表标题改为识别出的第一行；没有文字仍显示「复制的图片」。
- 预览在图片下方显示识别的文字，可选中；「复制文字」位于预览底部信息栏、删除按钮旁，长文字滚动时保持可见，只复制，不写入历史。待识别、未识别到文字、识别失败、已关闭、超过像素上限、需要迁移时显示对应说明；其他系统不在预览中显示，只在偏好设置说明一次。面板打开期间沿用打开时的快照，新的识别结果在下次打开面板时出现。
- 关闭后停止识别，并删除所有已识别的文字，恢复默认标题，重建对应索引并清理索引中的旧片段。重新开启后重新识别全部图片。
- 识别失败的图片不自动重试，重新开启功能时再试。删除、清空或自动清理的图片不再识别；识别途中被删除或功能被关闭时，丢弃结果。数据库写入出错时（如磁盘已满），后台等待约 30 秒再试，避免每 2 秒重复识别同一张图片。

## 存储

数据库升级到版本 4，事务内完成，失败不改变已有数据：

- `history.ocr_state`：图片 0 待识别、1 已完成（文字可为空）、2 失败；文字等其他类型及超过 5000 万像素的图片为 1。新增 `(ocr_state, position)` 索引供后台按最新优先查询。
- `history_ocr`：识别文字（最多 512 KiB，按 UTF-8 边界截断）及其搜索文本，随历史条目删除。只为识别出文字的图片保存。
- `settings.ocr_enabled`：功能开关，作为唯一状态来源。

识别文字不放进 `history_content`：SQLite 更新一行会重写整行，写入或清除文字会重写图片内容。实测 20 张 2 MiB 图片的行内更新耗时 351 ms、写入 4 MiB 日志，独立表为 1.9 ms、0.1 MiB；位于图片之后的列在搜索时还要读过图片的溢出页。识别后搜索前缀由识别文字和第一行标题组成，再接来源；被替换的默认标题不再命中。

识别耗时期间不持有数据库写锁：短暂读取下一张待识别图片，识别后在事务中写入结果；写入条件要求条目仍为待识别、功能仍开启且开关轮次未变。进程内轮次在写锁下更新，防止关闭后立即重新开启时接受上一轮的文字或错误；设置事务失败只会让待识别图片重试，无需增加数据库字段。更新索引时原文档只含标题和来源，不需要立即合并索引；关闭功能删除文字时会合并，避免已删除文字残留在全文索引中。

## 代码边界

- `image_text.go`：后台循环、结果整理（以换行连接，截断与标题）、History 的读取/写入/开关方法；识别函数作为参数传入，测试使用假实现。
- `image_text_tiles.go`：区域划分与合并（区域按行优先，区域内沿用 Vision 的阅读顺序，跨区域的行接在首段之后），与平台无关，可单独测试。
- `image_text_darwin.go`：通过 purego/objc 加载 Vision，在锁定线程、utility QoS 的后台 goroutine 中识别；大图在 Go 中解码一次，每个区域编码为 PNG，使用独立的请求与 autorelease pool，识别后归还解码内存。
- `image_text_other.go`：其他系统不启动识别，详情状态为不支持。
- `sqlite.go`、`sqlite_history.go`：版本 4 结构、升级与插入。
- `history_view.go`：详情返回识别文字与状态。
- `desktop*.go`、`preferences*.go`：启动后台识别、复制文字（由 `imageTextCopy` 生成与采集相同标识的文字条目，再走 `deliver` 的仅复制路径）、偏好设置开关。
- 前端：预览、浏览器演示样例、演示偏好设置。演示的示例截图即 `testdata/image-text/demo.png`，测试校验其内嵌数据与 Vision 识别结果一致；从 JSON 演示迁移后，新数据库默认开启识别。
- 评测：`testdata/image-text-eval/` 生成语料并评分，`TestImageTextEvaluation` 用发布的识别流程输出结果，仅在设置语料路径时运行。

## 验收

1. 后台识别把文字写入数据库，搜索可以找到图片；标题变为第一行。
2. 识别途中删除、清空、关闭功能时不写入结果；失败不重复识别。
3. 关闭后文字、标题和索引恢复，搜索不再命中；开启后重新识别。
4. 版本 3 数据库升级后已有图片进入待识别；新数据库直接使用版本 4；迁移流程保持校验。
5. 真实 Vision 在 macOS 上识别测试图片中的中英文和代码。
6. 预览显示文字与状态，「复制文字」不写入历史；浏览器演示可体验搜索、复制、开关。
7. Go 竞态测试、前端测试、Go/MyGo 静态检查及平台构建通过。
