# 选择数据目录设计

日期：2026-11-18
分支：`main`

## 目标

现在只能用启动参数 `--data-dir` 换数据目录。这次在偏好设置里加上：选一个文件夹，把数据搬过去，校验后切换并重启；旧位置的数据在新位置启动成功后删除。

范围只是本机的另一个位置，比如另一块盘或另一个文件夹。网络盘不在范围内。同步盘（iCloud、OneDrive、Dropbox）提醒，但不拦。

## 数据位置记录

- 默认数据目录：macOS 是 `~/Library/Application Support/Clipnest`，Windows 是 `%APPDATA%\Clipnest`。目录名来自编译期变量 `defaultDataDirName`，正式版是 `"Clipnest"`，测试版用 `MYGO_LDFLAGS="-X main.defaultDataDirName=Clipnest.verify"` 隔开，重启后也不会碰到真实数据。
- 换过位置后，默认目录里有一个 `data-location.json`：`{"dir": "…", "previous": "…"}`。`previous` 只在刚搬完、旧数据还没删时存在。用 `writePrivateJSON` 写。改回默认位置时删掉这个文件。
- 启动时按这个顺序决定数据目录：`--data-dir`（设置页锁定，不能改），记录文件，默认目录。
- 约定：除默认目录外，记录在案的目录里一定有 Clipnest 数据（`clipnest.sqlite3`，或旧版的 `history.json`/`phrases.json`）。启动时下面几种情况都算「数据目录不可用」：记录文件读不出来，目录不见了，没有权限，目录里找不到数据。不会悄悄新建空库，也不会写到别处。默认目录永远可用，缺了就新建，和现在一样。

## 选目标

设置页和启动对话框共用 `resolveTarget(picked)`：

1. 选的是默认目录：就用默认目录，它本来就有 `updater.json` 和记录文件，不套用下面的规则。
2. 选的文件夹里有 Clipnest 数据：问「改用这里的数据 / 取消」。改用时不复制，记录直接指过去，当前位置的数据原样留着。改用之前先在当前进程里打开那份数据一次（`prepareDataDir`），打不开就提示原因、不写记录，免得每次启动都打不开。
3. 选的文件夹是空的：直接用它。
4. 选的文件夹非空但没有 Clipnest 数据：用它里面的 `Clipnest` 子文件夹，免得选了 `D:\` 时数据散在盘根。子文件夹已有 Clipnest 数据，按第 2 条；有别的文件，拒绝。

判断「空」时忽略 `.clipnest-move-*`、`.writer.lock`、`.DS_Store`、`desktop.ini`。

拒绝：就是当前位置；在当前数据目录里面；不可写；当前还是 JSON 存储（提示先迁移）。

同步盘按路径识别：iCloud 云盘（`~/Library/Mobile Documents`）、`~/Library/CloudStorage/*`、Windows 的 `OneDrive`/`OneDriveConsumer`/`OneDriveCommercial` 环境变量所指目录、`~/Dropbox`。确认框里提醒同步可能弄坏数据库，多台电脑同时用会冲突。

## 搬移

1. 点「更改…」，打开选择文件夹的对话框，可以新建文件夹，默认停在当前位置的上一级。交给 `resolveTarget`。
2. 确认框写明最终路径；搬完会重启；旧位置的数据在新位置启动成功后删除；搬移期间不记录新的复制。同步盘再加一句提醒。
3. 主线程把 `d.busy` 设上：剪贴板监听跳过、面板编辑和打开面板都被挡住，和一键迁移一样。面板开着就先收起，交还它的读事务。偏好设置显示「正在移动数据…」，按钮都灰掉。
4. 后台线程 `Storage.MoveTo(target, commit)`：
   - 拿 `s.mu` 和 `h.writeMu`，先把没写进数据库的历史写进去，再拿常用语的锁和数据库写锁。不拿 `h.mu`：主线程读暂停状态要用它，复制可能要好几秒。
   - 给目标目录加写入锁，清掉之前留下的 `.clipnest-move-*`，新建临时目录。
   - `VACUUM INTO` 把数据库写到临时目录，复制 `excluded-apps.json`、`privacy.json`、`shortcut.json`（存在的才复制）。
   - 校验：`integrity_check` 是 `ok`，每张表的行数和原库一致，JSON 逐字节相同。
   - 逐个改名到目标目录，目标里已有同名文件就停下。同步目录。
   - `commit()` 写记录文件（`dir`=新，`previous`=旧）。失败就删掉刚放进目标的文件。
   - 关闭数据库，存储标为已关闭。
5. 成功后主线程 `mygo.App.Relaunch()`。失败就清除 `d.busy`，提示「移动失败：…，仍使用原位置」，不重启。
6. 新进程用新位置打开存储。成功后先把记录改成只有 `dir`（正式生效），再删旧位置 Clipnest 自己的文件：数据库及 `-wal`/`-shm`/`-journal`、上面三个 JSON、旧版两个 JSON、`.writer.lock`。别的文件不动。旧目录空了而且不是默认目录，就把文件夹也删掉。设置页提示「数据已移到 …」。

「恢复默认位置」走同一套流程，目标是默认目录。

## 出错

| 时机 | 结果 |
|---|---|
| 取消选择、目标被拒绝 | 什么都不变，设置页提示原因 |
| 复制或校验失败（含磁盘满） | 删临时目录，释放目标的锁，恢复记录。不重启 |
| 改名到一半、写记录失败 | 删掉已放进目标的文件，记录不变，继续用旧位置 |
| 写完记录后崩溃 | 下次启动按第 6 步走完 |
| 复制中崩溃 | 记录没变，用旧位置启动。临时目录下次搬到这里时清掉 |
| 新位置打不开 | 记录里有 `previous`：改回旧位置（是默认目录就删记录文件），尽量删掉这次的副本，用旧位置启动，设置页提示原因 |
| 正式生效的记录写不进去 | 用新位置继续，旧数据先留着，提示原因。下次启动再试 |
| 删旧文件失败 | 记录已生效，不回退。提示「旧位置的文件没能删除，可以手动删除：路径」 |
| 启动时数据目录不可用 | 见下一节 |

识图文字在 `VACUUM INTO` 之后写的结果不会带过去，新位置会重新识别。

## 数据目录不可用

存储在 `App.Run` 之前打开，对话框要等应用跑起来，所以这时走一段单独的启动：不打开存储，只运行 App，弹对话框写明路径和原因，按钮：

- **重试**：`Relaunch()`。
- **重新选择…**：选文件夹，交给 `resolveTarget`（以默认目录为当前位置）。有数据就把记录指过去重启；没有数据就问「这里没有 Clipnest 数据，要从空白开始吗？」，同意的话先在那里建好空库，满足上面的约定，再重启。
- **改回默认位置**：删记录文件，重启。原来那份数据不会被删，之后可以用「更改…」→「改用这里的数据」接回来。
- **退出**。

全程不新建或写入那个不可用的路径。macOS 上「文稿」、外接盘等没有权限时也走这里，原因里写上去系统设置的「文件与文件夹」中允许。

## 设置页

「本地存储」组加一行「数据位置」：完整路径，按钮「打开文件夹」「更改…」，不在默认位置时多一个「恢复默认位置」。`--data-dir` 启动时按钮灰掉，说明由启动参数指定；JSON 存储时提示先迁移。搬移和启动收尾的结果显示在这一行下面。

## 测试

单元测试（macOS 和 Windows CI 都跑）：

- 决定数据目录：优先级；记录坏了、目录没了、目录里没数据都算不可用；默认目录永远可用。
- `resolveTarget`：四种情况，默认目录不套子文件夹规则，拒绝当前位置及其里面，忽略临时目录和锁文件，同步盘识别。
- `MoveTo`：历史（含图片）、常用语、识图文字、设置完整搬过去，JSON 逐字节相同；没写进库的历史先写进去；复制、校验、改名、写记录各自失败时，目标里不留 Clipnest 文件，旧存储照常读写；目标被别的实例锁住时拒绝。
- 不卡主线程：钩子停住复制时，读暂停状态不用等。
- 启动收尾：先生效再删；只删 Clipnest 的文件；默认目录不删，其他目录空了才删；新位置打不开时回退并删副本；删除失败只提示。
- 不可用对话框：按钮到动作的对应写成纯函数测。
- 设置页：路径和按钮、灰掉的条件、「恢复默认位置」的显示条件、提示文字。

真机测试（先问；空闲；保存恢复剪贴板；退出已安装的 Clipnest；用 `Clipnest.verify` 默认目录；测完清理）：

- Mac：用 `hdiutil` 建小磁盘镜像当另一块盘，搬过去，检查数据完整、旧文件删除；推出镜像后启动看不可用对话框，挂回后「重试」；「改回默认位置」；搬到「文稿」时的系统权限提示。
- Win11 云桌面：在自己的会话里用 `subst X:` 模拟盘符，搬过去，`subst /d X:` 后看不可用对话框。

测不到：真实 U 盘和移动硬盘、Win10。
