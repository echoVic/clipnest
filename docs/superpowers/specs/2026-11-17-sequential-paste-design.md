# 顺序粘贴设计

日期：2026-11-17
分支：`feat/sequential-paste`（基于 `feat/privacy-hardening`）

## 目标

填表、迁移数据时常要把几段内容依次粘到不同位置：先连续复制好，再在目标里每按一次 ⌘V（Windows 为 Ctrl+V）粘出下一条。现在只能每次打开面板挑一条。

只支持 macOS 和 Windows，它们有自动粘贴；Linux 不提供这项操作。

## 开始

- 历史页的 ⌘/ 动作菜单新增「从这条起顺序粘贴（N 条）」。N 是选中条目和它上面的条目数，也就是当前列表的第 1 到第 N 条。列表跟随当前的搜索和筛选，看到什么就粘什么。
- 只在选中第 2 条及以后时出现（N ≥ 2），常用语页不提供，没有单独的快捷键。
- 队列按复制顺序排列：先粘第 N 条（最早复制的），最后粘第 1 条。图片也可以排进去。
- 最多 100 条、内容合计不超过 64 MB；超过时提示「顺序粘贴最多 100 条，请从更近的一条开始」或「内容太大，请从更近的一条开始」。
- 开始时从面板打开时的历史快照读出全部内容，不受之后的复制、删除影响。被遮罩的密钥粘贴原文，与普通粘贴一致。
- 开始后面板收起，焦点回到原应用；剪贴板在第一次 ⌘V 之前不变。
- 已经在顺序粘贴时再开始一次，替换原来的队列。

不能开始时，面板提示原因，不改剪贴板：

- macOS 未允许辅助功能：「允许辅助功能后才能顺序粘贴」。
- ⌘V 注册失败（被其他应用占用）：「⌘V 被其他应用占用，无法顺序粘贴」（Windows 写 Ctrl+V）。
- 面板已更新、列表变了：「列表已更新，请重新选择」。

## 每次 ⌘V

顺序粘贴期间 Clipnest 用全局快捷键注册 ⌘V。按下时：

1. 取消 ⌘V 注册，免得自己发出的按键再被截住。
2. 把第 k 条写入剪贴板，并记下剪贴板版本，记录时不当作新的复制。
3. 向当前最前面的应用发送 ⌘V。最前面是哪个应用就粘到哪里，可以在不同应用、不同输入框之间切换。
4. 约 100 毫秒后重新注册 ⌘V。

细节：

- Windows 上用户还按着 Ctrl，只补发 V；如果这时 Ctrl 已经松开，就发送完整的 Ctrl+V。macOS 发送带 ⌘ 标记的 V。
- 最前面是 Clipnest 自己的窗口（面板搜索框、偏好设置）时，原样补发 ⌘V，队列不前进。面板失焦即隐藏，所以面板显示时就算在前；macOS 的面板接收按键却不让 Clipnest 成为前台应用，不能只看前台应用。
- 面板里正常粘贴（回车、数字键、常用语）时，发出的 ⌘V 不能被队列截住：粘贴前同样先取消注册，100 毫秒后再注册。
- 写剪贴板或发送按键失败：停止顺序粘贴并在面板和托盘提示原因。写入失败时补发用户的 ⌘V，让它照常粘贴剪贴板里已有的内容；发送失败时第 k 条已在剪贴板上，⌘V 已释放，用户可以手动再按一次。
- 重新注册失败（被其他应用抢走）：停止，提示「⌘V 被其他应用占用，顺序粘贴已停止」。

## 结束与显示

- 结束时机：最后一条粘出后；托盘菜单或面板横幅里点「停止」；10 分钟内没有再按 ⌘V；退出 Clipnest。结束时立即释放 ⌘V。
- 结束后剪贴板保留最后粘出的那条，不恢复，和普通粘贴一致。
- 进行中：
  - macOS 菜单栏图标旁显示剩余条数；Windows 托盘提示写「顺序粘贴 · 剩 N 条」。
  - 托盘菜单第一项是「停止顺序粘贴（剩 N 条）」。
  - 打开面板时顶部显示横幅「正在顺序粘贴，剩 N 条，每次 ⌘V 粘贴下一条」和「停止」按钮。
- 期间的复制照常记录，不改变队列。

## 已知限制

- 取消注册到重新注册之间约 100 毫秒；这段时间里再按一次 ⌘V，会粘出同一条。按住 ⌘V 自动重复也一样（Windows 注册时带 `MOD_NOREPEAT`，不重复触发）。键盘事件监听可以避免，但需要 MyGo 没有提供的原生代码，这次不做。
- Windows 上以管理员身份运行的应用会拦下 SendInput，这时队列照样前进，但内容没有粘进去。

## 实现

- `sequence.go`：队列状态机 `pasteSequence`，依赖都通过 `sequenceOps` 注入：注册与取消快捷键、写剪贴板、判断最前面是不是自己、发送按键、延时回调、状态变化通知。每个延时回调带代号，停止或重新开始后，过期回调不起作用。
- `sequenceItems`：从面板快照按当前搜索和筛选读出第 1 到第 N 条，校验第 N 条是选中的那条，按复制顺序返回，检查条数与大小。
- `Desktop.StartSequence(session, revision, q, kind, index, id)`、`Desktop.StopSequence()`；`PanelState.Sequence` 为剩余条数，0 表示没在进行。
- `deliver` 发送粘贴按键前调用 `pasteSequence.release()`。
- 原生：`pasteAccelerator()` 返回 `Command+V` 或 `Ctrl+V`；`nativeBridge.PasteHeld()` 不等按键松开直接发送粘贴（macOS 需辅助功能，Windows 按 Ctrl 状态决定是否补 Ctrl）。
- 托盘菜单改为右键时按当前状态生成。
- 前端：`entryActions` 增加 `sequence` 项；`perform` 调用 `StartSequence`；横幅读 `state.sequence`；浏览器演示只提示「演示：已开始顺序粘贴 N 条，桌面版每次 ⌘V 粘贴下一条」。

## 测试

- 状态机（假的注册器、按键、剪贴板和定时器）：开始、前进、最后一条后结束、手动停止、10 分钟超时、自己窗口在前时补发不前进、`release` 期间不前进、注册失败、重新注册失败、写入失败、发送失败、过期回调无效、重新开始替换队列。
- `sequenceItems`：顺序、跟随搜索和筛选、选中条目对不上、条数和大小上限。
- 前端：菜单项只在历史页且 N ≥ 2 时出现，文案带条数，执行时发出的参数；横幅显示与停止。
- 实机：macOS 与 Windows 上连续粘贴到文本编辑器和不同输入框，⌘V 在结束后恢复正常。Windows 云桌面的门户可能截住 Ctrl+V，关掉剪贴板同步后再试；仍然不行就如实说明。
