## 0.1.5 存储决策更新

本次按用户确认的方向新增 SQLite 与旧用户一键迁移。以下早期 JSON 保护和响应实验记录保留为历史背景；新安装默认使用 `clipnest.sqlite3`，已有 JSON 必须由用户点击迁移。

- 采用 `modernc.org/sqlite v1.61.0`，保留无 cgo 和跨平台构建；代价是新增驱动依赖及更大的二进制。正式库使用 WAL、最多两个连接、FULL 同步与外键约束；迁移暂存库使用单连接、DELETE 日志，发布前关闭。
- 历史的顺序、来源、时间戳与正文/图片分表；图片为 BLOB，正文保留原文。变更只写受影响记录，排序不会更新内容表。常用语与历史共用数据库但保留各自提交语义。
- 迁移锁定历史保存与常用语修改，写入同目录的私有临时数据库，读取后逐项比对，再关闭并替换到正式路径。切换成功后才清理旧 JSON；清理失败继续使用 SQLite 并允许重试，数据库损坏不回退旧 JSON。
- 面板显示「一键迁移 / 稍后」，偏好设置保留入口。成功后提示消失；重复点击、迁移失败和已切换但清理失败分别处理。新安装不显示迁移提示。
- SQLite 取消条数限制；默认历史正文与图片共 512 MiB、不过期，容量和天数可配置，0 为不限。设置与清理原子提交，常用语不受影响。JSON 兼容模式保留 200 条 / 32 MiB 上限直至用户主动迁移。保留 500 条常用语上限和两秒脏数据保存周期。
- `history_view.go` 通过读取事务冻结面板的排序与内容。每次打开先在工作线程保存待写内容，再读取首屏 50 条摘要；详情按 ID 读取。窗口隐藏、关闭、失焦和粘贴离开时取消读取，后台自动清理不使当次编号变化。手动修改历史或策略则重建会话，陈旧的分页、详情与粘贴请求会被拒绝。
- `history.go` 的 SQLite 路径仅保留待提交变更；成功后只移除本次提交的队列前缀，保留并发新增。缓存内容超过 32 MiB 或 1024 个待写操作时停止接收新内容并提示磁盘问题，避免写入失败导致内存无界增长。此限制不限制已存历史数量。
- 元数据独立存储类型、标题、摘要、大小、来源和顺序；重复制用递减顺序值移至首位，不批量重排。SQLite 保存小写搜索前缀和来源，片段索引与精确匹配维持中文、大小写和字面 `%_` 子串语义；查询耗时仍受候选数量和索引溢出影响。
- 容量只计算正文和图片。派生搜索文本、索引、数据库空闲页与 WAL 不计入策略；长时间保持面板打开可能延迟删除和日志回收，文件大小不保证等于配置容量。
- 所有 SQLite 写事务共享写入锁，防止两个延迟事务同时读后写产生 `SQLITE_BUSY_SNAPSHOT`。修改策略与待提交历史在同一事务内写入，并按新策略清理；放宽限制不会先按旧限制删除。历史和常用语插入均携带发起时的面板会话，读取延迟期间重开面板不会把请求转向新的目标应用。
- 本轮分页与清理验证：完整 Go 竞态测试、vet、Node 28 项测试、差异格式检查通过；用例覆盖 735 条重启恢复、末页与正文分离、冻结快照、并发待写队列、策略放宽、事务回滚、取消读取及 v1 数据库升级。写入冲突与放宽策略用例先观察失败，再验证修复。
- 独立原生验证程序使用临时数据库和 10,000 条生成文本、暂停系统剪贴板采集，经真实 WKWebView Bridge 读取末页及详情，首屏仅 7 个列表行；12 次隐藏/重开、删除、清空、策略保存、陈旧历史与延迟常用语插入拒绝均通过。它验证当前代码的原生接线，不等于签名安装包、跨应用真实粘贴或全套多显示器验收。浏览器另验证万条历史的跨页选择、缓存边界、错误重试和加载事件乱序。
- 迁移阶段验证记录：Go 全量测试、race、vet 与 Node 15 项测试通过；darwin/amd64、linux/amd64、windows/amd64 的无 cgo 测试二进制编译通过。真实 v1 文件先复制到临时目录，200 条历史和 3 条常用语完成迁移及重启逐项比对，原文件未改动。浏览器验证使用模拟桥接，覆盖成功、失败重试、清理重试、重复点击、新安装不提示、深色与窄窗口；尚未对打包后的 WKWebView 迁移按钮做真机端到端验收。
- 同机同配置的未压缩开发二进制由 17,898,114 字节增至 24,246,210 字节（约 +6.1 MiB），不是最终通用安装包体积；本轮未测完整启动延迟、峰值内存或迁移中强制断电。

## SQLite 搜索优化

`search_index.go` 使用现有驱动内置的 FTS5，不增加依赖。将小写搜索文本的 1/2/3 rune 连续片段编码成 ASCII 十六进制词项，避免分词、标点、NUL 和大小写规则改变搜索行为。每条最多 4096 个不同片段；达到预算后加入 `overflow` 词项，该条始终参与精确候选扫描，避免截断索引造成漏报。索引不保存正文，编码词项仍属于本机私密数据。

- 1–3 字查询命中的片段就是精确子串，直接读取摘要；溢出条目通过原文核对。更长查询最多选择六个分散片段缩小候选，再用完整查询核对。大部分匹配先检查前缀或来源，跨字段匹配只拼接足够长的字节尾部，避免逐条复制完整长文本。
- `search_results.go` 每个查询只扫描一次候选并取得有序整数 ID。最多缓存两个查询，各 16384 个 ID，后续页只读取摘要。更多结果只保留总数并按页重查，不截断结果；淘汰时清除数组引用。
- `Desktop.Search` / `Desktop.Page` 携带查询 revision。新查询在取得事务锁之前取消旧查询的子 context；不取消面板读取事务，详情和原始剪贴板内容继续可用。前端在 60 ms 防抖之前通知取消，忽略过期结果和错误；面板仍在加载时等待读取事务就绪。
- 数据库升级为 schema v3，事务内回填稳定 `search_id` 并建立索引；该 ID 不随 VACUUM 的隐式 rowid 变化。新增和来源变化与索引在同一写事务提交，来源未变的重复制不重建索引。
- 内容为空的 FTS 表删除后会留下 tombstone，单独开启 `secure-delete` 不足以清除旧词项。因此删除、过期清理和来源替换在提交前执行一次索引合并；清空直接执行 `delete-all`。测试先复现旧片段留在 shadow table，再验证当前表中片段消失。打开的面板仍可能持有旧 WAL 页，不能把这理解为即时物理擦除保证。

在 Apple M2 Pro、Go 1.27.1 上，以 10,000 条、每条约 2 KiB 的生成文本测量。相同数据库和查询，旧 SQLite 双扫描作为参照；每个 benchmark 执行五次，候选每次清除查询 ID 缓存。下表是单次平均值，不含索引构建、Bridge、60 ms 防抖或界面渲染，也不是 P95 或产品延迟承诺。

| 查询场景 | 旧扫描 | 索引查询 |
|---|---:|---:|
| 稀有双字词「独特」 | 83.31 ms | 0.53 ms |
| 稀有长词「needle独特关键词」 | 79.34 ms | 1.36 ms |
| 未命中「missing词」 | 156.29 ms | 0.37 ms |
| 常见双字词「文本」（全部匹配） | 34.88 ms | 14.20 ms |

同一生成器另测后台批量写入成本，100 条一事务，不包含 `newEntry` 构建：万条短文本由 1473 ms 增至 2956 ms，数据库由 51,544,064 增至 53,161,984 字节（约 +1.54 MiB，平均额外 0.15 ms/条）。千条约 128 KiB 文本由 1941 ms 增至 6908 ms，数据库增加约 0.21 MiB，平均额外约 5 ms/条。重复正文使词项去重效果较好；不将这些成本外推到高熵文本或频繁清理。删除及来源变化需要索引合并，其代价未单独量化。

回归覆盖中文短词、大小写、代码符号、NUL、emoji、组合字符、跨字段子串、索引溢出、分页缓存与大结果重复翻页、过期请求、执行中的 SQL 中断、索引升级、VACUUM、写入回滚及索引片段回收。独立原生程序用临时数据库、暂停剪贴板采集，在真实 WKWebView 验证万条数据的中文输入、100 条命中、跨页摘要、详情和 revision 失效；仍仅渲染 7 行。浏览器另覆盖快速输入与慢查询模拟。

复跑：`go test -run '^$' -bench '^BenchmarkSQLiteSearch' -benchtime=5x -count=1 .`。该生成器含重复文本、稀有词和完全未命中场景；溢出文本、很多候选或更大的历史可能仍需要扫描。

## 独立存储设计

沿用当前 v1 history.json / phrases.json，而非复制 Shelf 的 Store 或托管目录结构。历史自动采集与常用语人工编辑继续保留不同提交语义。

- `storage.go:decodePrivateJSON`：文件必须是普通文件且不超过 256 MiB，消费完整单个 JSON 文档；末尾只允许空白。未知 v1 扩展字段仍允许。不支持版本继续拒绝。
- `history.go:openHistory`：重新验证内容并重建 ID，遇到坏条目停止加载，保持原件，不静默丢弃。合法旧文件保持兼容。
- `storage_lock_unix.go` / `storage_lock_windows.go`：main 读取数据前取得数据目录内 `.writer.lock`，锁持有到程序退出。macOS/Linux 用内核 flock；Windows 用 LockFileEx。跨进程实际验收在 macOS，Windows 仅编译验证。此锁只约束合作实例，旧版本程序或任意外部编辑器不受锁保护。
- `writePrivateJSONWith`：同目录私有临时文件（0600）→ 编码 → 文件同步 → 关闭 → 替换 → 目录同步。替换前失败保持原件，正常返回失败时清理本轮临时文件。
- 替换后目录同步失败返回独立错误，不假装回滚。常用语保持与已替换文件一致并转只读，停止重试，重启再读磁盘。历史不推进 saved 代次，继续保存当前最新状态，而非重放旧快照。
- 不自动恢复旧备份，防止删除/清空的私密内容复活。没有引入加密、日志或隐式迁移。未来需要升级格式时，应另行定义显式迁移及备份清理合同。
- macOS/Linux 的文件和目录同步不等于已证明断电绝不丢失；未做断电测试。Windows 保持文件同步+替换，没有目录 fsync 保证。
- 历史仍每 2 秒保存，异常退出可能丢失尚未保存的最近复制；人工操作错误仍按现有接口表达。

## 响应改动

`search.go` 为不可变 Entry 保存不落盘的派生小写搜索文本。在捕获/加载时构造，冻结面板继续持有本次内容，不按仅有内容 ID 的共享缓存错误复用来源应用。

- 查询时不再逐条拼接并转小写整段内容。
- 保持原有顺序、大小写不敏感、子串跨字段匹配、类型过滤、空数组形状和摘要输出。
- 代价：每条多一份内存搜索表示，构造开销移到采集/加载；采集路径、启动时间和 RSS 未做 A/B 验收。这是有边界的查询收益，不是整体性能已通过。

`web/responsiveness.js` 与 `web/app.js`：

- 方向键只更新旧/新选中项，不再逐次遍历全部 DOM 行；保留 aria-selected、activedescendant 与键盘选择语义。
- 当前上下文详情请求合并、LRU 缓存最多 12 条；列表刷新、重新唤起清空，失败不缓存，旧请求失败不能删除新请求。
- Unicode 字符计数不构造完整字符数组。
- 前端耗时收益未用浏览器 A/B trace 测量，仅验证功能及操作范围。
